# Sweet Lesson — Esc回帰の修正

スクロール統合で、Escが操作モード退出として先にreturnし、作品の97%の場面の入力処理に届かなくなっていた。133.0秒以上・134.38秒未満でstageにフォーカスしている場合は、作品のEsc演出を先に処理する。この区間のリピート・再押下は追加発火せず、操作モードとフォーカスを保つ。区間外は既存どおり操作モード退出。修飾キー・入力欄・本文は捕捉せず、制作ログのEsc閉鎖を優先する。

変更はwalk/walk.jsの入力優先順と、時刻条件を共有するinEscWindowだけ。描画・タイムライン・白い部屋・曲・終了後の自動回転は変更していない。

## ローカル確認

ビルド・構文チェック・diff check成功。専用Chrome/Metal/tier4、OSへの音声出力は--mute-audioで抑止。

[実ブラウザ15項目](review/esc/results.json)すべてpass。実際のキーボードイベント（isTrusted=true）で133.62秒のEsc発火とフォーカス維持を確認した。133.66秒付近で描画上のEscキーが約3.5mm沈み、134.38秒の自動演出より前にcompact: cancelledを描画。早い入力後の自動時刻で合成クリックは追加発火しない。133.0秒は受付、132.99秒と134.38秒は操作退出。リピート・再押下・入力欄・制作ログ・修飾キー・無操作時の既定演出を確認。通常入力4項目・Tab5項目も再実行しpass。

白い部屋は59.9〜88.9秒に映像が切り替わり、自由入力は61〜80.1秒。時間条件による移行で、いつでも独立して入れる入口はない。白い場面で曲が再生継続してunmuted、Spaceで一時停止して実Wキーで3.3秒歩行し、位置が移動しても足音呼び出しは0だった。記事の「音がしない」は足音については一致し、音楽全体を消す意味なら一致しない。

## 終了後の向き（読み取りのみ）

終了後はctrl.tickが_tickEpiへ分岐するため、再生中の約4秒のタイムライン復帰とは別。epiIdle=2.5秒、epiDrift=0.12m/sで窓近くの目標へ漂い、yaw/pitchも窓へ向ける意図的な処理。reduced-motionやQA holdでは漂流しない。実機の回転を観察していないため、その現象がこの処理かは未確定。

yawの更新はatan2の目標角から現在yawを直接引き、最短角度差へ正規化していない。現在yawによって大きく回る可能性がある。操作中にはドラッグ慣性もある。終了後のacting判定にはWASD等とyaw速度は含むがQ/Eのturnを直接含めていない。これらはコード上の事実で、実機現象との対応は未検証。今回この回転処理は変更していない。

## 別の観測（今回変更しない）

複数のQA操作後、部屋操作モード中に常設の再生ボタンを押してもclickイベントが届かないケースを観測した。Spaceによる再生・一時停止は成功した。stageのfocusoutで操作ラベルが短くなり、中央寄せされたバーのボタンが押下中に移動することが原因の候補。Esc回帰とは別で、今回修正対象に含めていない。
